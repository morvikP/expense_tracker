# 💰 Трекер расходов

Веб-приложение для учёта личных расходов. Позволяет добавлять траты по категориям, отслеживать общую сумму и разбивку по категориям. Все данные хранятся в браузере (`localStorage`).

## ✨ Возможности

- ➕ Добавление трат с категорией, суммой, датой и описанием
- 📋 Список всех трат с сортировкой от новых к старым
- 🗑️ Удаление трат с мгновенным пересчётом
- 💵 Общая сумма всех расходов (крупно)
- 📊 Разбивка по категориям
- 💾 Автосохранение в `localStorage` — данные не теряются после перезагрузки
- 🎨 Адаптивный дизайн для мобильных устройств
- 🚫 Пустое состояние с подсказкой, когда трат ещё нет

## 🛠️ Технологии

- **HTML5** — структура страницы
- **CSS3** — стилизация (чистый CSS, без фреймворков)
- **JavaScript (ES6+)** — вся логика приложения

## 🔧 Как использовать

1. Откройте `index.html` в браузере или перейдите по ссылке деплоя
2. Выберите категорию, введите сумму и дату (по умолчанию — сегодня)
3. Нажмите «Добавить» — трата появится в списке
4. Для удаления нажмите ✕ рядом с тратой
5. Данные сохраняются автоматически — можно перезагрузить страницу

## 🧪 Проверка localStorage

Откройте DevTools (F12) → Application → Local Storage → выберите `file://` или домен. Вы увидите ключ `expense_tracker_expenses` с JSON-массивом всех трат.

## 📝 Защита проекта

### Что такое localStorage и чем отличается от обычной переменной?

`localStorage` — это встроенное в браузер хранилище типа «ключ-значение». В отличие от обычной JS-переменной, данные в `localStorage`:
- **Сохраняются после закрытия браузера** и перезагрузки страницы
- **Привязаны к домену/протоколу** — разные сайты не видят данные друг друга
- **Не зависят от жизненного цикла страницы** — переменная живёт пока открыта страница, localStorage — постоянно

В режиме **инкогнито** `localStorage` работает, но данные удаляются при закрытии последнего окна инкогнито. В **другом браузере** данные не будут доступны — у каждого браузера своё изолированное хранилище.

### Где в коде сохранение и загрузка?

- **Сохранение**: функция `saveExpenses()` — строка `localStorage.setItem(STORAGE_KEY, JSON.stringify(expenses))`
- **Загрузка**: функция `loadExpenses()` — строка `localStorage.getItem(STORAGE_KEY)` с последующим `JSON.parse()`

`JSON.stringify` нужен, потому что `localStorage` хранит только строки. Массив объектов JavaScript нужно сериализовать в JSON-строку. `JSON.parse` восстанавливает массив обратно.

### Что будет, если в localStorage положить невалидный JSON?

Если через DevTools вручную записать некорректный JSON (например, `{bad json}`), то `JSON.parse` выбросит исключение. Код обрабатывает это в `try/catch` — в блоке `catch` возвращается пустой массив `[]`, и приложение продолжает работать без ошибок.

### Где происходит подсчёт сумм?

- **Общая сумма**: функция `calcTotal()` — проходит по всем тратам через `reduce` и суммирует `amount`
- **По категориям**: функция `calcByCategory()` — проходит по всем тратам и накапливает суммы в объекте

Оба подсчёта **пересчитываются каждый раз заново** из массива `expenses`, а не хранятся отдельно. Это гарантирует, что после удаления или добавления траты суммы всегда актуальны и не рассинхронизируются.
